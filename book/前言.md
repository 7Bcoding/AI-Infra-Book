# 前言

一张新 GPU 的标称算力翻了一倍，部署在上面的模型能快多少？这个问题很难只靠硬件手册回答。模型可能受限于显存带宽，也可能在等待网络通信。即使模型运行得更快，用户还可能要在队列里等待。

在大型科技公司从事 AI Infra 工作时，我经常遇到这样的问题。负责模型的同事关注计算和模型效果，负责内核的同事关注访存和指令，负责服务的同事则要考虑并发、延迟和故障。每个人都能从自己的位置看到问题的一部分。要做出可靠的判断，往往需要把这些信息放在一起。

我写这本书，是想梳理 AI Infra 中相互关联的知识，让不同背景的读者都能找到理解问题的入口。书从可以手算的数学模型讲起，逐步讨论设备怎样执行它、数据怎样送到设备、许多台机器怎样一起训练，以及模型交给用户后怎样评估。模型、内核和平台的取舍，有时可以放在同一笔账里算。例如，一个新算子省下三毫秒，先要看看它在请求的哪一段，再谈这三毫秒中有多少能省到用户身上。

不妨带着一个问题来读：用户已经输入了一段很长的文字，为什么下一个词还迟迟不来？做模型的人可以让几个查询头共用一组键和值。这段历史随之变小，每个查询头却仍要算自己的分数。写内核的人还可以让几组查询一起用刚取来的数据，否则纸上省下的空间未必能换来同样多的读取节省。做服务的人打开请求记录，也许发现最大的延迟发生在模型开始执行之前。此时即使把一次注意力算快一半，队列里的请求照样得等。三个人面对的是同一个词，各自需要的证据很不一样。

书中常把一个看似有效的改动放回原题再算一遍。对于训练，要把速度换算成达到同一质量需要的天数。对于服务，要看同一批到达的请求中有多少按时拿到了合格结果。论文有时给出一个改写计算的等式，芯片工程师为它设计了可用的指令，而部署它的人还得处理短输入、内存不够和设备故障。了解每一步是在什么条件下成立，也就更容易判断它能否用到自己的机器上。

## 谁适合读这本书

如果你有线性代数、微积分和概率论的基础，还没有系统学习过计算机或深度学习，可以从第一章开始。第二章介绍矩阵如何存储、程序如何访问数据，第三章用一个小网络手算前向、反向和参数更新。遇到较陌生的系统概念时，不必一次记住所有术语，可以先理解例子中的数据从哪里来、经过什么计算、结果要送到哪里。

如果你已经从事模型、内核、网络或平台工作，也可以从自己关心的章节读起。比如，熟悉注意力公式，想弄懂长上下文为什么拖慢服务，可以连着看第五章的历史表示、第十章的算子访存与第二十三章的请求调度。若要查一次训练停顿，可以先看第十七章怎样排查输入，再读第十八、十九章的网络与同步，最后对照第二十一章的专家负载。附录按这些现场问题整理了查阅位置。

## 怎样使用图和实验

书中的插图配合正文推导。阅读时间线时，可以先看每项工作何时开始、何时结束，再检查它依赖的计算或传输。阅读存储布局图时，可以选一个元素，沿着图中的地址、缓存行和设备位置追踪它的访问过程。

算例中的数字通常经过简化，便于手算。章末练习都附有解答，不少章节还提供可以在普通电脑上运行的 Python 实验。读者可以改变输入尺寸、到达时间或分配方式，比较结果和自己的预期。论文与真实系统的性能数据则需要结合设备、软件版本、工作负载和测量方法理解。正文会尽量说明这些条件。

我希望读者读完后，面对一张训练曲线、一段执行轨迹或一份芯片规格表，能够提出有依据的判断，也知道还需要哪些测量。更重要的是，当问题跨越模型、硬件和系统边界时，能与不同领域的工程师一起找到原因。
